## 一、UI 组件规范

### 1.1 KPI 卡片规范（6 张）
- 字段固定：标题 / 主值 / 环比(chg) / 风险徽标
- 主值着色：level==red → 主值红色；level==yellow → 主值橙色；否则默认墨色
- 环比空态：`chg` 为 `—` 时用灰字 + 虚线边框徽标，不报错、不占红黄
- 风险徽标：卡片左上角小圆点（红/橙/灰），与告警等级同源
- 全 6 张卡统一接入风险着色（修复 B2：原仅广告花费/估算净利 2 张有 level）

### 1.2 风险告警列表规范
- 每条告警 = 两行布局：
  - 行1：风险标签（颜色）+ 标题 + 明细文本
  - 行2：操作按钮「去处理」「转待办」
- 文本区 `min-width:0; word-break:break-word`，长文本不挤压按钮（修复 A2）
- 组件化：新增 `U.alertItem(a, handlers)` 统一渲染（修复 A3），页面不再散写裸 `<button>`

### 1.3 风险标签颜色规范
| 语义等级 | 颜色 | 映射来源 |
|---|---|---|
| 紧急 | 红 `#E74C3C` | `a.level==='red'` |
| 高 | 橙 `#E67E22` | `a.level==='yellow'` |
| 中 | 灰 `#95A5A6` | 其余（含 info） |

标签文本建议：`紧急` / `高` / `中`（替代原 `U.tag` 的蓝绿红黄混用，统一为三档语义）。

### 1.4 空状态组件
- 新增 `U.empty(text)`：居中图标 + 灰字「暂无数据 / text」
- 覆盖点：
  - 销售&广告趋势图（cSales）、转化漏斗（cFunnel）、店铺销售构成（cPie）无数据时各显示占位（修复 A5）
  - 告警列表为空时显示「今日无异常，恭喜 🎉」
  - KPI 整组无数据时显示区块级占位

## 二、数据逻辑

### 2.1 KPI 空值处理
- `chg` 计算：无上期 → 返回 `{text:'—', cls:'k-chg-empty'}`，UI 用灰虚线样式（修复 B2）
- 综合 ACOS 卡：对接保本线/目标线给出等级（修复 B3）——见 C2
- 销售额/订单/转化率 三张卡：无风险时 `level=null`，不强制着色

### 2.2 告警自动排序算法（修复 B1 缺口）
保留现有「合规>账户>库存>利润>广告>节点 + 红先于黄」主排序，新增：
- **账户级信号补齐**：新增账户类告警生成（见 C1），使铁律第 2 优先级不再形同虚设
- **去静默截断**：`slice(0,20)` 改为「前 20 条展示 + 顶部统计面板显示『共 N 条』+ 其余按域折叠/展开」，不再无提示砍掉（修复 B1-②）
- **分组/优先级可见**：列表按 6 大域分段，每段带域标题 + 该域数量，优先级肉眼可读（修复 B1-③）

### 2.3 倒计时 / 过期处理（修复 B1-①/C4）
- 节点(活动提报)到期计算：`d = daysTo(deadline)`
  - `d < 0`：不再 `return` 丢弃，改为「已过期」灰态 + 文案「已超期 N 天」
  - `0<=d<=nodeRedDays(默认7)`：紧急红
  - `nodeRedDays<d<=nodeYellowDays(默认30)`：高橙
- 倒计时组件：`U.countdown(deadline)` 渲染「剩 N 天」并在过期后置灰

### 2.4 转待办状态流转（修复 C6/B 系列）
- 唯一映射：待办 `source = 'alert:'+a.id`，写入前查重，已存在则不重复生成
- 回写：告警对象追加 `a.todoId` 与 `a.todoAt`，UI 显示「已转待办 · 查看」
- 到期日：默认 `now + 7d`，可改
- 闭环：待办页标记完成时回写 `a.resolvedAt`

## 三、业务交互

### 3.1 跳转路径（SKU/广告/节点告警埋点）
| 告警类型 | 点击「去处理」跳转 |
|---|---|
| 库存告急 / 负利润（SKU 维度） | `#/inventory` 或 `#/profit`（按 SKU 定位） |
| 广告 ACOS 超标 | `#/ads` |
| 活动/提报节点临近 | `#/peak` |
| 合规/账户 | `#/compliance` |
| 退货率 | `#/returns` |

### 3.2 顶部统计面板
- 告警列表顶部一条汇总卡：`紧急 X · 高 Y · 中 Z · 合计 N`，红橙灰三色小方块
- 点击某色块可筛选该等级（可选，阶段 3 视情况）

### 3.3 批量操作
- 勾选多条告警 → 「批量转待办」「批量标记已处理」
- 阶段 3 先实现「批量转待办」，标记已处理后置灰

## 五、业务规则确认（⚠️ 待跨境电商专家 / 你拍板，以下为建议口径，非定稿）

**C1 · 账户类告警信号**
- 建议数据源：店铺绩效通知（Performance Notifications）、账户健康分(Account Health Rating)、商品停售/抑制(Suppressed/Blocked)、二审/验证请求
- 建议触发：健康分 < 阈值(默认 200？)、存在未处理绩效通知、有 ASIN 被抑制
- 需确认：是否新增 `account_health` 表？演示数据怎么造？

**C2 · 综合 ACOS 超标口径**
- 建议：综合 ACOS 对标「加权保本 ACOS」（各 SKU 保本 ACOS 按销售额加权）与「目标 ACOS」(默认 25%)
- 红：综合 ACOS > 加权保本线；橙：> 目标线
- 需确认：保本线用加权保本还是类目均值？目标线默认值？

**C3 · 库存告急阈值**
- 现状 `stockRed:14 / stockYellow:30`（可售天数）
- 建议：US/EU/JP 补货 lead time 不同，长期应按店铺 `leadDays` 复核；短期保留 14/30 默认，加注释
- 需确认：14/30 是否覆盖三站点实际？要不要分站点配置？

**C4 · 活动节点过期处理**
- 建议：过期节点「置灰保留 + 超期提示」，不消失；`nodeRedDays:7 / nodeYellowDays:30`
- 需确认：过期节点是否仍计入「合计 N」？还是单独「已过期」分组？

**C5 · 退货率告警口径**
- 建议：退款/退货率 > returnRateRed(默认 15%) 红、> returnRateYellow(默认 8%) 橙；与 FBA 丢失/损坏索赔区分（索赔走 `claims` 表，不在此告警）
- 需确认：退货率取订单级还是金额级？阈值 8%/15% 是否合理？

**C6 · 转待办状态流转**
- 建议：alert→task 唯一映射（`source` 去重）、回写 `todoId`、默认到期 +7d、待办完成回写 `resolvedAt`
- 需确认：转待办后原告警是否自动从「今日异常」移除？还是保留并标记「已转待办」？
